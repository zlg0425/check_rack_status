# 性能监控脚本使用指南

## 概述

`monitor_performance.py` 是一个持续性能监控脚本，用于监控应用的各种性能指标，包括：
- API响应时间（平均、中位数、P95、P99）
- 错误率
- 并发性能（吞吐量）
- 内存使用情况
- 自动告警（当性能指标超过阈值时）

## 功能特性

1. **持续监控**：定期检查API性能指标
2. **多指标统计**：响应时间、错误率、吞吐量等
3. **自动告警**：当性能指标超过预设阈值时自动告警
4. **日志记录**：所有监控数据记录到日志文件
5. **历史数据**：性能指标保存到JSON文件，便于后续分析
6. **性能报告**：生成详细的性能分析报告

## 安装依赖

```bash
pip install requests psutil
```

## 使用方法

### 1. 基本使用（持续监控）

```bash
# 使用默认配置（每60秒监控一次）
python monitor_performance.py

# 指定API URL和监控间隔
python monitor_performance.py --api-url http://127.0.0.1:8888 --interval 30
```

### 2. 单次监控

```bash
# 只执行一次监控周期，然后退出
python monitor_performance.py --once
```

### 3. 生成性能报告

```bash
# 生成报告并输出到控制台
python monitor_performance.py --report

# 生成报告并保存到文件
python monitor_performance.py --report --report-file performance_report.txt
```

### 4. 自定义配置

```bash
# 指定所有参数
python monitor_performance.py \
    --api-url http://127.0.0.1:8888 \
    --interval 30 \
    --log-dir logs \
    --metrics-file performance_metrics.json
```

## 命令行参数

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `--api-url` | API服务器URL | `http://127.0.0.1:8888` |
| `--interval` | 监控间隔（秒） | `60` |
| `--log-dir` | 日志目录 | `logs` |
| `--metrics-file` | 性能指标文件 | `performance_metrics.json` |
| `--report` | 生成性能报告并退出 | `False` |
| `--report-file` | 报告输出文件 | 控制台 |
| `--once` | 只执行一次监控周期 | `False` |

## 监控指标

### API响应时间指标

- **平均响应时间**：所有请求的平均响应时间
- **中位数响应时间**：响应时间的中位数
- **P95响应时间**：95%的请求在此时间内完成
- **P99响应时间**：99%的请求在此时间内完成
- **最小/最大响应时间**：最快和最慢的请求时间

### 错误率指标

- **错误率**：失败的请求占总请求的百分比
- **成功率**：成功的请求占总请求的百分比

### 并发性能指标

- **吞吐量**：每秒处理的请求数（QPS）
- **并发平均响应时间**：并发情况下的平均响应时间

### 内存使用指标

- **进程内存**：监控脚本占用的内存
- **系统内存使用率**：系统整体内存使用情况

## 告警阈值

默认告警阈值（可在脚本中修改）：

| 指标 | 阈值 | 说明 |
|------|------|------|
| 平均响应时间 | > 1000ms | 警告 |
| P95响应时间 | > 2000ms | 警告 |
| P99响应时间 | > 5000ms | 严重 |
| 错误率 | > 5% | 严重 |
| 并发吞吐量 | < 100 请求/秒 | 警告 |

当指标超过阈值时，会在日志中输出告警信息。

## 输出文件

### 日志文件

- **位置**：`logs/performance_monitor_YYYYMMDD.log`
- **格式**：文本格式，包含时间戳和日志级别
- **内容**：每次监控周期的详细结果和告警信息

### 性能指标文件

- **位置**：`performance_metrics.json`（默认）
- **格式**：JSON格式
- **内容**：所有监控周期的性能指标数据
- **保留**：最近1000条记录

### 性能报告

- **格式**：文本格式
- **内容**：最近24小时的性能统计摘要

## 自定义监控端点

编辑 `monitor_performance.py` 文件中的 `MONITORED_ENDPOINTS` 列表：

```python
MONITORED_ENDPOINTS = [
    {"path": "/api/status", "method": "GET", "name": "status"},
    {"path": "/api/upload", "method": "POST", "name": "upload"},
    {"path": "/api/fota", "method": "POST", "name": "fota"},
    # 添加更多端点...
]
```

## 自定义告警阈值

编辑 `monitor_performance.py` 文件中的 `ALERT_THRESHOLDS` 字典：

```python
ALERT_THRESHOLDS = {
    "api_response_time_avg": 1000,  # 平均响应时间阈值（毫秒）
    "api_response_time_p95": 2000,  # P95响应时间阈值（毫秒）
    "api_response_time_p99": 5000,  # P99响应时间阈值（毫秒）
    "error_rate": 5.0,  # 错误率阈值（百分比）
    "concurrent_throughput": 100,  # 并发吞吐量阈值（请求/秒）
}
```

- **前台运行**：按 `Ctrl+C`
- **后台运行**：找到进程ID并发送终止信号
  ```bash
  # Linux/Mac
  pkill -f monitor_performance.py
  
  # Windows
  taskkill /F /IM python.exe /FI "WINDOWTITLE eq monitor_performance.py"
  ```

## 最佳实践

1. **监控间隔**：根据实际需求设置，建议30-60秒
2. **日志轮转**：定期清理旧日志文件，避免占用过多磁盘空间
3. **告警阈值**：根据实际性能基线调整告警阈值
4. **定期检查**：定期查看性能报告，识别性能趋势
5. **性能基线**：记录正常情况下的性能指标，作为对比基准

## 故障排查

### 问题：连接错误

```
[ERROR] status 连接错误: 服务器可能未启动
```

**解决方案**：
- 确认API服务器已启动
- 检查 `--api-url` 参数是否正确
- 检查网络连接

### 问题：请求超时

```
[ERROR] status 请求超时
```

**解决方案**：
- 检查服务器响应是否正常
- 增加 `--timeout` 参数（需要修改脚本）
- 检查服务器负载是否过高

### 问题：内存占用过高

**解决方案**：
- 减少监控间隔
- 定期清理 `performance_metrics.json` 文件
- 减少监控的端点数量

## 与现有测试脚本的区别

| 特性 | `test_performance.py` | `monitor_performance.py` |
|------|----------------------|-------------------------|
| 用途 | 一次性性能测试 | 持续性能监控 |
| 运行方式 | 执行后退出 | 持续运行 |
| 数据保存 | 不保存 | 保存到JSON文件 |
| 告警功能 | 无 | 有 |
| 报告生成 | 控制台输出 | 可生成文件报告 |
| 适用场景 | 开发测试 | 生产监控 |

## 总结

`monitor_performance.py` 是一个功能完善的性能监控工具，可以帮助您：
- 持续监控应用性能
- 及时发现性能问题
- 分析性能趋势
- 优化应用性能

建议在生产环境中使用此脚本进行持续监控，并定期查看性能报告以识别潜在的性能问题。
